Why it's needed

When a guest CPU has nothing to do it idles, and the kernel's Gunyah driver puts the VM's CPU thread to sleep straight away. The next interrupt for that CPU — a disk or network completion, say — has to wake it the long way: through the hypervisor, an interrupt on the phone's first core, and the scheduler, before the guest runs again. A Windows guest idles thousands of times a second, and every I/O it waits on pays that trip.

What it does

Before the thread sleeps, it waits a moment (at most 200 µs) for the wakeup to arrive, the way KVM's halt polling does on PCs. A completion that comes within that window goes straight back to the guest. The window adapts per guest CPU: it grows while wakeups arrive soon after an idle and shrinks to nothing when they don't, so an idle VM costs next to no extra power.

The built-in driver is not changed; the module only steps in on the vCPU's wait. Turn it off at run time with su -c 'echo 0 > /sys/module/gunyah_halt_poll_gki_6.6/parameters/halt_poll_ns'. It cannot be unloaded while a VM is running.

原因

客户机的 CPU 没事做时会进入空闲，内核里的 Gunyah 驱动会立刻让这个 VM CPU 的线程睡下。下一个给它的中断——比如磁盘或网络完成——只能绕远路叫醒它：先经过虚拟机监控器，再到手机第一个核上的中断，再经过调度器，客户机才能接着跑。Windows 客户机每秒空闲上千次，每次等 I/O 都要走这一趟。

功能

线程睡下之前，先等一小会（最多 200 µs）看唤醒会不会马上来，就像电脑上 KVM 的halt polling。在这段时间内到达的完成会直接回到客户机。等待时长按每个客户机 CPU 自动调整：唤醒总在空闲后不久到来就加长，等不到就缩到 0，所以 VM 空闲时几乎不额外耗电。

内核自带的驱动不做改动，模块只在 vCPU 等待时介入。运行时关闭：su -c 'echo 0 > /sys/module/gunyah_halt_poll_gki_6.6/parameters/halt_poll_ns'。VM 运行期间无法卸载。
